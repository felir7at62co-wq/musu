# 仿真人短剧总控

Agent 处理文本与质量决策，剧变插件（`jubian_*`）是唯一多媒体生成通道。production_mode=live_action。开工读取项目、当前分镜、主体设定、模型目录、已有任务和本地状态；不凭旧记录重新生成。

## 设置与创作

- 当前项目与分镜已保存的模型、平台、比例、分辨率、时长，以及用户已确认的交付规格优先；用实时目录校验支持范围，不用默认 Seedance 2.0、720p 或固定 14 秒覆盖。冲突先查明，不能静默换模型/降规格。图片通道同样读取已选配置；多候选未锁定时按工具提示由用户在设置中选择。
- 常见 1–4秒镜头、9 个有效字/秒、36 字和尽量少用旁白是创作建议，不是普遍硬门禁；超出时记录警告并复核节奏。15 字拆句也按语义判断，不强拆原句。原文、顺序、说话人、发声方式与资产身份必须保留；dialogue、同场画外音以及原文要求的旁白/心声均不得被静默丢弃或强制改成当场对白。动作、场景和摄影说明不冒充发声。
- 完整连续镜头按当前分镜时长与真实模型上限打包，收束时间计入总时长，不截断台词凑包。场景、时空、服装变化分别处理。编译前读当前工具 schema；`drama_shot` 的 `max_submit_seconds` 必须来自实际分镜/目录约束，而非猜测常量，创作警告见 `report.warnings`。本地旧编译器不支持的字段不能冒称已支持。

## 正式资产

先读取主体设定，再处理真正缺少的资产。缺失重要角色资产默认先索取用户参考图，按 `tweet-drama-core` 本地参考图流程归档、逐图审核并取得用户确认，收费生图前运行 `style_references.py <项目目录> <role_id> check`；缺图或证据不全就暂停，不自动安装、启动或调用小红书。资产图按项目确认的版式；角色、场景、道具不可混用。生成资产仍须自动审核（实际视觉检查）与确认出演，max_review_attempts=3 是定向审核上限，不是自动花满次数的许可。

非本地生成候选必须具有生成 `material_id`；`jubian_asset confirm_casting` 成功且父资产回查一致后才写 asset_confirmation=verified、official=true。`isLocal=1` 正式主体可无生成 material_id，但须实时回读 materials/get：属于当前 scriptId、已在主体设定、isUsed=1、hsAssetStatus=Active、URL 和 hsAssetId 与父资产及 picker 一致。满足后跳过该资产生成链，在 writer 合法阶段记录 skipped 与 skipped_with_official_local_evidence 及门禁证据。本地 manifest 不能替代远端来源。

## 提交与费用

1. 主体视频只走 `jubian_storyboard` 的 `select_assets`（免费 isGenerate=0）→ `prepare_video`（只读 preview）→ `submit_video`（收费 isGenerate=1）。禁止 direct `POST /admin/aigc/video/task/create`。
2. 每次收费前自检项目归属、正式资产身份及顺序、当前规格、目录报价和预计费用、授权范围及已有任务。收费须有当前用户对具体项目、操作范围及预算的明确授权；token 存在不等于花费授权，不得继承其他操作者或历史项目的授权，也不以预算配置代替授权。未授权、范围不明或超出项目/预算/规格授权时先询问并获准；在当前用户已明确授权的范围内自主执行，不逐笔索要即时批准。记录预计调用数、费用与回读 realCost。
3. submit_video 的 idempotency_key 必须等于 preview fingerprint。结果未知、超时或 pending 时查已有任务/子结果，保持原 key，禁止换 key 盲目付费重投。生成后核对每个子项 ID、名称、URL 和顺序；身份丢失停止该分支并诊断。
4. 确认终止失败后才评估根因、已有费用、可用恢复路径和剩余授权。工具 retry 仅在其无结果且未计费条件满足时可用；必要的新任务须有修正证据和新 preview，不是未知任务的重提。连续无进展或预算不足停止该分支，不能无限付费试错。

## 依赖调度

source → episodes；已有正式资产直接复用，缺失资产才经提示词→生成→审核→确认出演。镜头创作可与独立资产准备并行；匹配、提交等待各自实际依赖就绪。同一分镜 select_assets→prepare_video→submit_video 保持有序；不同集/独立任务可并行，去字幕等待期间可做选曲、草稿及其他镜头，不强制整部剧串行。

分层产物：source、episodes、style、asset_prompts、asset_candidates、official_assets、shots_and_matches、video_tasks、reviewed_videos、draft、export。唯一流程状态由 pipeline_state writer 写入；上游变化只使受影响下游 stale，成功且输入未变的收费结果复用，不手改完成标记。

## 异步去字幕与转高清

抽帧并听音审核身份、服装、场景、道具、动作、口型、连续性和文字。无内嵌字幕才记 subtitle_cleanup=not_required；有字幕则用目录中明确选定的擦除模型提交一次，保存 task ID 并记 pending。SD2.5（Seedance 2.5）默认直接使用通过内容审核的原片，不自动提交或等待转高清；用户明确要求高清处理时才另行执行。其他模型也不能仅因源分辨率低于导出尺寸就自动付费转高清。needs_upscale 只表示分辨率差异，不是必须调用的指令；项目持续制作授权不等于强制购买所有后处理。普通导出缩放可按用户确认的尺寸执行，但须分别如实记录源分辨率与输出尺寸，不能称为已做高清增强。此规则优先于工具旧版“必须先转高清”的提示；仍须检查实际画质、人物、字幕和音画。

模型自主安排后续查询：利用可用调度能力，或先推进独立工作再在后续轮次回读既有任务；不在工具中干等、不忙轮询，也不把等待责任交给用户。pending/unknown 保留任务身份和下一次查询计划；五分钟或任何等待时长都不是放行最终交付的依据。confirmed failed 按费用与恢复规则评估，未恢复不得伪造 clean。

pending 原片可供内部草稿/预览，必须明确标注“未完成，非最终交付”。clean 只在选用的擦除结果实际回读并审核无残字、无损坏后成立；URL 存在或任务成功不足以证明质量。替换为高清或另一版本后重新检查实际选用文件。

## BGM 情绪分段

一集的 BGM 必须多于一首（用户硬要求）：每集至少 2 段、至少 2 首，按正文情绪分段选曲，切点落在镜头包边界上。逐段记录选曲与时间、来源、理由、音量与过渡、试听结果；跨集复用由 `drama_bgm` 的批次门禁强制（每集至少 2 首不同曲目、集内不重复、整批单曲最多 2 集、每集至少 1 首全新、切点在包边界 0.05 秒内），不合格就在写出任何产物前失败，不是提醒。执行 `tweet-drama-background-render` 的音频与过渡规则；曲目及选曲渠道须满足发行用途的许可证要求。

## 完成定义

所有使用资产为 official=true；原文/说话人/身份与真实供应商约束检查通过；所有最终选用视频经内容、实际分辨率和音画审核，字幕状态只能 clean 或 not_required；实际发声字幕完整且时间来自真实音频；BGM 选曲计划与试听复核可追溯；最终 MP4、SRT、来源映射和可编辑草稿齐全，并对实际最终导出文件做 QA。pending/unknown/failed 或仅有草稿不能标记最终完成。保留项目已确认交付规格。
