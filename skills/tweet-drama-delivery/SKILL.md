# 交付模板组装（整部剧一份）

把**用户确认通过**的集，按技能自带 `assets/template.json` 的九目录定义 归集成**整部剧一份**的交付目录。只做归集：不生成图片、不调剧变、不重渲成片、不动上游产物。

模板目录**只读**，不要改它。保留项目已确认交付规格；组装前确认映射指向的实际母版已通过音画、规格、字幕和来源 QA，使用视频的字幕清理必须 clean 或 not_required。pending 草稿不是最终交付，用户确认集号不能代替实际文件审核。

## 视频禁用标签

组装前用 `drama_video` list/inspect 查本项目 `video-bans.json`；SHA256 只标记具体字节版本，同字节副本同样禁用。ban 的 labels 至少一个自由可读标签，reason 可选，不要证据；标错用 unban。查询无标签或解除禁用不能当审核通过，也不替代用户确认。禁止通用 FFmpeg、手写脚本或手工复制绕过禁用。

`assemble_delivery.py` 在复制前按映射母版自身字节检查禁用，坏清单拒绝继续。当前镜头目录不是历史母版来源证明，未用镜头的禁用不得当作该母版的禁用；当前镜头风险另行核查。旧成片可能使用已替换源：当前输入无禁用不能证明历史成片通过，须核对实际母版，已知问题成片也应按自身 SHA256 禁用。检查是项目范围的官方路径门禁，不拦截任意外部命令。

## 一个项目一份模板，不是每集一套

交付目录 `<项目>\delivery\` **本身就是**模板的 9 个目录骨架。集是「往里加」，不是「各建一套」：

- `00成片\` 累加全剧已确认的集：`01.mp4`、`02.mp4`、`03.mp4`……
- `01主角\`、`02海报\`、`05剧本&简介\` 都是**整部剧只放一次**的东西，不按集复制。

## 九宫格责任划分

| 目录 | 放什么 | 谁负责 |
|---|---|---|
| `00成片` | 全剧已确认的成片，命名 `<集号>.mp4`；**只要视频** | **本流水线**，一集一个文件 |
| `01主角` | 男主/女主的资产图，**必须一男一女**，其中至少一个是主角；有男女双主就放双主。**整部剧只放一次** | **本流水线** |
| `02海报` | **整部剧的海报，不是每集海报**。6 个比例：1:1、16:9、9:16、2:3、3:4、7:10。**整部剧只放一套** | **本流水线**（有就放；没有就留空并报「缺」） |
| `03资产` | — | 不用管 |
| `04精彩片段` | — | 不用管 |
| `05剧本&简介` | **原剧本复制一份** + 一份简介，`txt` 格式、**少于 200 字**。**整部剧各一份** | **本流水线** |
| `06AI工程文件` | — | 不用管 |
| `07剪映工程截图` | — | 不用管 |
| `08第X集是付费点` | — | 不用管 |

后 5 个（03/04/06/07/08）**不由本流水线填**：脚本显式跳过并打印，不要自作主张塞东西进去。

`00成片`里**只有视频**。母版、聊天副本、封面 `*_封面.jpg`、SRT、交付说明都是流水线内部产物，留在 `export\`。

只分发九目录定义，不包含或复制 `即梦AI 用户协议.pdf` 等第三方文件。显式 `TWEET_DRAMA_TEMPLATE` 必须指向存在的目录；覆盖只校验该目录，不导入文件或改变九目录定义。

## 内部控制文件不进交付根

交付根只能是模板那 9 个目录，**不许多出文件**。配置都在 `<项目>\_probe\delivery-config\`：

| 文件 | 作用 |
|---|---|
| `_confirmed_episodes.json` | 门禁账本：登记用户确认通过的集 |
| `confirmed-films.json` | 成片母版映射：`01` → 该集确认过的具体母版路径 |
| `主角.json` | `01主角` 的男女主声明（`{"male": [...], "female": [...]}`） |
| `简介.txt` | 简介主本，脚本校验后分发到 `05剧本&简介\简介.txt` |

## 门禁：只有用户确认通过的集才组装交付

> **只有用户确认通过的集才组装交付。**

没有机器可读的审批位——`pipeline_state.json` 里 export 阶段停在 `review`，那不代表用户点头。确认只来自用户本人的话。没登记的集，脚本拒绝组装并以非零退出；用户说了「第 N 集过了」之后才追加，不要替用户推断、不要为了跑通先登记。

### 确认的不是集号，而是该集的具体母版路径

同一集在 `export\` 下常有多份母版（`_成片`、`_成片_规范版`、`_成片_新首包版`、`delivery-epNN`……），规格各不相同。**用户确认的是具体哪一个文件，不是一个集号**，所以 `00成片` 只认显式映射：

```json
// <项目>\_probe\delivery-config\confirmed-films.json
{"films": {
  "01": "export\\<剧名>_第01集_成片_新首包版.mp4",
  "02": "export\\<剧名>_第02集_成片.mp4"
}}
```

- 映射缺了、或映射指向的文件不存在 → **失败**，并把 `export\` 下这一集的候选全列出来；**脚本不自行挑**，哪怕只剩唯一一个候选也只报不选。
- 交付文件名固定为 `<集号>.mp4`；内容是逐字节复制，不重编码、不转码，哈希与母版一致。
- 换母版 = 改这一行映射后重跑；不要手动往 `00成片` 里拷文件。

## 用法

```powershell
# 组装第 1 集；再跑 2、3 集就是把它们追加进同一份交付
# 在本技能目录执行；其他工作目录用技能加载器返回的完整脚本路径
python scripts/assemble_delivery.py `
  --project "<已确认的项目目录>" --episode 1
```

- `--project` 项目目录；`--episode` 要追加/更新的集号（`1` / `01` 都行）
- `--out` 可选，默认 `<项目>\delivery\`；项目内仅允许 delivery 子树，其他输出须独立于项目和上游来源。拒绝含链接的输出目录，避免同步删除上游文件。
- 只写交付目录，其余全部只读

脚本先建模板的 9 个目录骨架，再填本流水线负责的 4 个：

- `00成片\NN.mp4` ← `confirmed-films.json` 里该集显式指定的母版（映射缺了就报错并列候选，不猜）
- `01主角\` ← `主角.json` 里人工声明的男主角与女主角图（文件名照抄 `assets\**\lead_*.png`）
- `02海报\` ← `export\`/`assets\` 下名字含「海报」或 `poster` 的图片（整部剧的海报）
- `05剧本&简介\` ← `source\original\*` 整份复制 + `简介.txt`

物料缺了就是缺：**不要伪造，不要拿封面冒充海报，不要拿别的集顶**。

## 主角：一男一女，性别由人声明

项目里**没有**机器可读的性别字段——`assets_manifest.json` 的 `state_or_costume` 是服装描述，角色名也不带性别。所以性别来自人工声明一次：`_probe\delivery-config\主角.json`。`male` / `female` 任一为空、或声明的文件名在 `assets` 下找不到，脚本就报错。

## 简介

主本在 `_probe\delivery-config\简介.txt`，脚本校验后分发到 `05剧本&简介\简介.txt`。中文，**去空白后少于 200 字**（≥200 直接失败）。依据剧本与项目名写清设定、钩子与结局走向；**一份总简介服务全剧**，不按集重写。

## 自检

脚本在 stdout 的 `<<<ASSEMBLY_REPORT>>>` 标记间输出 JSON：九目录内文件的存在与大小、简介字数，以及成片的 ffprobe 分辨率/帧率/时长/码率；探测失败如实记录。脚本不落盘报告、不核对复制前后 SHA256，也不自动清理交付根多余项；调用方须另行核验这些交付要求，不能把 stdout 报告当作全部 QA 已通过。ffprobe 支持 `MUSE_FFPROBE_EXECUTABLE`、`DSH_FFPROBE`、`FFPROBE_PATH` 或 PATH。

## 常见错误

- 每集建一套 9 目录 → 整部剧只有一份交付目录，集是加进同一个 `00成片\`。
- 每集都放一遍海报/主角/剧本 → 这三样全剧各一份。
- 把 `02海报` 当成每集海报 → 是**整部剧**的海报，6 个比例。
- 在交付根放配置或说明文件 → 配置放 `_probe\delivery-config\`。
- 把资产图放进 `03资产` → 资产图只进 `01主角`，`03资产` 不归我们。
- 主角目录只放一张 → 必须一男一女。
- 靠服装描述猜性别（「西装=男」）→ 项目里没有性别字段，只在 `主角.json` 里声明。
- 一集有多份母版时按名字挑一份 → 只认 `confirmed-films.json` 的显式映射，缺了就报候选并拒绝。
- 海报没有就跳过不报 → 必须显式列为「缺」。
- 拿 `*_封面.jpg` 当海报 → 封面是内部产物，留 `export\`。
- 简介按含空白的字数凑到 190 → 按去空白字符数算。
