# 后台成片

只消费内容审核通过的剧变结果和实际发声字幕。pending 只能做标注“未完成，非最终交付”的草稿/预览，模型安排后续查询与来源替换；最终必须 clean 或 not_required，未知或失败不可放行。对实际选用文件审核残字、损伤、分辨率及音画，不能只信成功状态或 URL。按来源映射硬切拼接；动作描述不得成为字幕。

输出最终 MP4、同名 SRT、渲染日志和可编辑草稿。渲染前用 ffprobe 校验每段真实时长；渲染后检查总时长、音视频流、黑帧、静音和字幕 cue 越界。编码失败时保留中间文件，只重跑失败集。

## 视频禁用标签

开工先用 `drama_video` list/inspect 查本项目标签；ban 至少给一个自由可读 labels（如“人物对调”），reason 可选，不要证据。SHA256 标记具体字节版本，同字节副本也禁用。标错用 unban；查询无标签或解除禁用不等于审核通过，不替代下面的 hashreview。禁止改用通用 FFmpeg、项目手写 render 或复制旧成片绕过禁用。

`scripts/render_episode.py` 在任何 FFmpeg 前检查实际 `video/NN/shot_NNN.mp4`，无需选源审核 manifest 才能识别禁用；旧缓存缺来源哈希或来源变动时重建，发布最终路径前重查源和结果。失败不覆盖已有成片。检查只覆盖该项目官方执行路径，不拦截任意外部命令；历史成片缺来源映射时不能凭查询无禁用宣称通过。

## 审核证据绑定

使用当前渲染工具前读取 schema 和 prepare 输出。prepare 的 `shots[]` 每行在有显式 package 映射且 `episode_packages/NN/package.json` 存在时记录 `package_sha256`（不是顶层字段）。审核记录的 `package_sha256`、该选源行的值与当前 package 文件字节 SHA256 必须一致；`video_sha256` 独立匹配实际选用视频，并保留内容、字幕清理及抽帧证据。审核者须对照当前 package 检查实际视频，不能机械复制新哈希来批准旧视频。package 任何字节变化（含格式化、同镜头数重编译）都保守要求重新核验证据；缺证据保持 review，不标 completed。

## 已确认交付样式

SD2.5（Seedance 2.5）默认使用通过内容审核的原片合成，不自动调用或等待付费转高清。needs_upscale 只是分辨率差异提示，不是原片禁用或必须购买后处理的判定；其他模型也不得仅凭该字段自动付费。仅在用户明确要求高清处理时执行。用户确认的普通导出尺寸可以通过常规缩放实现，但要如实区分源分辨率、导出尺寸与高清增强，不冒称提升了原生细节。此规则优先于旧工具的强制高清提示，内容及音画 QA 不省略。

保留项目已确认的交付规格。下面是已有项目的渲染样式，不得反过来覆盖其他项目确认值；生成分辨率来自当前分镜，交付分辨率单独验收。使用 `scripts/render_episode.py` 或当前渲染工具前读取参数/schema；缺少所需能力先报告，不凭默认值宣称满足。最终输出须经 QA，渲染成功不等于验收完成。

- **输出** 1440×2560 @60fps，h264，目标码率 `24M`、上限 `30M`、bufsize `48M`，**码率下限 4.6 Mbps**（用户硬要求，交付前用 ffprobe 复核实际码率）。优先 `h264_nvenc`（`p5 -cq 19`）；探测失败自动回退 `libx264`，并把回退原因写进渲染日志。
- **正文字幕** SimHei 68、字间距 `-2`、白字 7px 黑描边、单行、无标点、按语义切分；ASS 用 1080×1920 设计坐标（`Alignment=2`、`MarginV=520`），成片输出 1440×2560。剪映草稿字幕字号独立，见 `tweet-drama-draft-build`。
- **水印只属于 FFmpeg 成片**：仅在右下角全程显示「内容由AI生成」，纯白无描边。右上角**不加水印**（原先的竖排「内容纯属虚构 请勿带入现实」已按用户要求删除）。剪映草稿同样不得添加任何水印轨。
- **音频** 已确认样式的主音频增益 `1.45`、BGM 音量 `0.24`、`alimiter=0.95` 限峰保持不变，试听时检查遮盖对白与爆音。**一集的 BGM 必须多于一首（用户硬要求）**：按正文情绪分段选曲；曲库不在本地，用 `bgm_match` 按正文情绪检索已发布的公开曲库（`catalogUrl` 指向 TOS 上的 `index.json`，只返回候选与实测 valence/arousal），**选定哪一首才用 `bgm_match download` 按 track_id 下载那一首**并校验大小与 SHA-256，落进它的下载缓存；选哪首由 agent 定夺，不得用坐标距离自动定稿（其 m-a-p/MERT-v1-95M 骨干许可仅限非商业用途，商业发行改用有商业许可的选曲渠道）。切点落在镜头包边界上；把选中的几首按节拍裁好、用 1.5 秒三角交叉淡化（淡化中心落在包边界）拼成一条 BGM 音轨（渲染器只接受一个 `--bgm` 文件），`-stream_loop -1` 后裁切到正文最后一个视频结束点，不进片尾。交付说明里逐段列出选曲与时间，并记录曲目/来源、理由、音量与过渡、试听结果。**跨集复用规则由 `drama_bgm` 以 `policy_findings` 报出，不拦截调用，但读到就必须照 `fix` 改完再交付**：每集至少 2 首不同曲目、一集内不得重复同一首、整批之内同一首最多出现在 2 集、每集至少 1 首是本批其它集没用过的、每个切点必须落在镜头包边界（容差 0.05 秒）、每段 `reason` 非空。批次 = 计划文件所在目录里所有含 `episodes` 数组的 JSON，阈值为部署配置项；返回的 `batch_episodes` 说明这次核对了哪些集。改计划前先用 `drama_bgm preview` 拿这份清单，别等 compose 才踩。
- **片尾 2 秒** 从**最后一镜 MP4 的真实尾部**抽最后一帧定格（固定 `-sseof -0.1`；**不要用 `-0.05`**——实测它在部分片子上不写文件却返回退出码 0，会静默产出一个空片尾），抽完必须用 `framemd5` 与「顺序解码的最后一帧」比对证明这一帧确实是真尾帧，对不上就按帧号 `select=eq(n\,N-1)` 重抽，仍对不上就停止出片；禁止用同号分镜 PNG 代替；叠加 `--ending-effect` 视频；音频取 `--ending-audio` 前 2 秒。两者默认用本包 `assets/ending_effect.mp4` 与 `assets/ending_audio.mp3`，用户另有授权的素材才换成它们的路径。定格图、结尾音频、结尾特效三者严格等长，特效只播放一次。
- **禁止**转场、额外音效、调色、滤镜、画面特效和花字；全片只有基础硬切与上述片尾特效。

## 本地依赖与入口

本包包含维护源码和片尾这两份素材（本技能目录下的 `assets/ending_effect.mp4`、`assets/ending_audio.mp3`），不包含 BGM、字体或 FFmpeg 二进制。安装 FFmpeg/ffprobe（需字幕滤镜和所选编码器）；路径读取 `DSH_FFMPEG_PATH` / `DSH_FFPROBE_PATH`，兼容 `FFMPEG_PATH` / `FFPROBE_PATH`，否则使用 PATH。muse-med Windows 产品另行捆绑 OFL 授权的 Noto Sans CJK SC，正文68、水印44及其余样式保持不变；Python 通过 `MUSE_FONTS_DIR` 和 `MUSE_FONT_FAMILY` 使用包内字体，正式 `drama_render` 由产品配置传入同一目录和字族。非产品部署保留原默认：字体由系统发现，或用 `DSH_FONTS_DIR` 指定已授权目录，需自行确认 SimHei 和 Microsoft YaHei 可用。脚本仅依赖 Python 标准库和相邻 `tweet-drama-core/scripts/video_bans.py`，建议 Python 3.11+，运行时用 `python -B`。

单集入口 `scripts/render_episode.py` 必须显式提供 `--bgm`（该集至少两首按情绪分段合成并试听通过的音轨）、`--ending-audio` 和 `--ending-effect`，后两者指向本技能 `assets/` 下的两份素材；批量入口 `scripts/render_batch.py` 使用 `--bgm-dir`，其中每集对应 `NN.mp3`，并同样必须提供两个片尾参数。文件缺失明确失败，不静默换成别的曲目或素材。音轨数量、选曲情绪与使用授权由项目分段记录和试听审核核验，脚本不从已混音文件推断曲目。生成规格服从当前模型目录与分镜，脚本的固定成片尺寸仅适用于上面已确认样式。

FFmpeg 的许可取决于安装构建的组件；音乐和字体各自需要使用授权。随包的两份片尾素材按操作者授权收录，只担保本机使用，不构成公开再分发授权。维护源码未附独立上游许可证；不把本机可访问等同于可公开分发。

## 交付两份

每集默认留两份交付物：`exports/<episode>.mp4` 直出成片，以及剪映专业版草稿目录。剪映草稿目录由用户明确指定，或从已配置的 `DSH_JIANYING_DRAFTS_DIR` 读取，同时在项目内保留归档副本。渲染前用 ffprobe 逐段核对真实时长，成片与草稿使用同一套镜头顺序和字幕时间。
